# Roadmap — éditeur d'objets Median XL 2.14.5

Fichier **unique** de suivi du projet (ce qui est fait, ce qui reste à faire, historique).
La documentation technique est ailleurs :
- `format-stash-mxl-2.14.5.md` : format des fichiers, tables du jeu, règles de l'infobulle, organisation du code ;
- `ihm.md` : fonctionnement de l'interface graphique ;
- `magic-find-affixes.md` : paliers de l'affixe Magic Find.

## Organisation
- **Répertoire de travail VS Code : `C:\Dev\D2 item edit`** — c'est la référence. Code Python à la racine, documentation dans `docs/`, traductions dans `lang/`, tests dans `tests/`.
- Le dossier `data/` (tables du jeu, `animdata.d2`, icônes dans `data/items/`) est extrait de l'installation de Median XL : l'éditeur demande le **dossier du jeu** au premier lancement (bouton « Game folder… », réglage `game_dir`) et propose de **reconstruire `data/` à chaque nouvelle version du mod** (empreinte `data/install.json` : version de `medianxl-version.mpq`, taille et date des archives `medianxl-*.mpq`, liste des fichiers extraits avec taille et md5 : fichiers supprimés ou abîmés détectés, réparation proposée). Reconstruction sûre (`mxl_install.rebuild_data`, environ 15 s) : extraction dans `data.new/`, contrôle, puis remplacement ; l'ancien dossier est gardé dans `data.old/`. En ligne de commande : `python extract_data.py [dossier du jeu]`. Le code ne modifie jamais `data/` en dehors de cette reconstruction acceptée par l'utilisateur (empreinte vérifiée par les tests).
- Sauvegardes du jeu : `%APPDATA%\MedianXL\save`. **Toujours modifier les fichiers jeu fermé** (écriture refusée tant que le jeu est ouvert) ; une sauvegarde `.bak-AAAAMMJJ-HHMMSS` est faite automatiquement dans `MXL Item Collector\backups` (seule la dernière est gardée ; à côté du fichier avant le 08/10).
- Lancement : `python mxl_gui.py` (interface, rouvre le dernier personnage et le dernier coffre choisis) ; `python mxl_items.py <fichier.stash>` (ligne de commande) ; exécutable Windows : voir « Fait ».
- **Dossier unique de l'utilisateur** (08/10, option C) : `%APPDATA%\MedianXL\save\MXL Item Collector\` (il voyage avec les sauvegardes du jeu) : `settings.json`, `library.json` (collection : vrais objets), `backups\` (sauvegardes des fichiers du jeu), `lang\` (langues ajoutées) ; `paths.HOME_DIR`, reprise des anciens emplacements au lancement (`mxl_home.migrate` : copie relue puis suppression, rien d'écrasé). Seul le cache des données extraites du jeu (`data/`, ~25 Mo) reste à part : dossier du programme (sources), `%LOCALAPPDATA%\MXL Item Collector` (exécutable). Réglages de l'utilisateur (`settings.json`, non versionné, communs aux sources et à l'exécutable) : langue, personnage et coffre choisis, dossier du jeu `game_dir`, priorités des stats, regroupement par set et sets dépliés de la collection. 
- **Tests de non-régression : `python tests/run_tests.py` puis `python tests/run_tests.py --base`** après chaque modification du code : cas indépendants (un échec ou un plantage n'arrête pas les autres ; dossier temporaire par cas ; `tests/common.py`), un fichier par thème :
  - affichage de deux coffres de référence dans chaque langue livrée, scénario d'écriture, sécurité, transfert entre coffres (`test_display_writes.py`) ;
  - qualité pondérée, contrôle de `data/` (`test_quality_install.py`) ; réglages, traductions ajoutées (`test_settings_rebuild.py`) ;
  - bibliothèque, infobulles du catalogue, recherche (`test_library.py`) ; collection (`test_collection.py`) ;
  - **documentation officielle** (`test_documentation.py`) : pages entières Tiered Uniques, Sacred Uniques, Sets (infobulles et bonus des sets), prises sur Internet et gardées en cache dans `tests/cache/docs/` (hors du dépôt, retéléchargées à chaque nouvelle version du jeu ou avec `--refresh-docs` ; sans connexion : copie en cache) ; différences connues listées avec leur raison ;
  - interface (`gui_tests.py`, un processus par test) ; `data/` inchangé ;
  - module complémentaire privé `mxl_editor` (s'il est présent : ses tests sont dans son dossier). Deux campagnes : sans option, base + module ; **`--base` : base seule** (module ignoré même présent, comme la version publique). Les deux doivent finir par « TOUT EST OK ».
  Coffres figés dans `tests/fixtures/` (le 2e dans `stash2/`), résultats attendus dans `tests/reference/` (`--update` après un changement d'affichage voulu et vérifié ; `--no-gui` sans l'interface ; `-k texte` : seulement les cas dont le titre contient ce texte ; `--slow` : en plus, construction et essai de l'exécutable Windows (environ 30 s) et reconstruction complète de `data/` depuis le jeu (environ 15 s), à lancer quand l'extraction ou l'emballage changent).
- Dépôt Git local : une branche par évolution, fusion dans `main` par défaut dès que les tests passent (« TOUT EST OK » vérifié), avec l'indication du commit de fusion pour revenir en arrière ; messages de commit terminés par `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Fait
**Lecture**
- Coffre personnel (`.stash`) et **coffre partagé** (`_sharedstash.shared`, même format, vérifié sur un coffre rempli en jeu : reconstruit à l'octet près) : toutes les pages, toutes les qualités rencontrées (basse, normale, supérieure, magique, rare, unique, set, runeword), runes (y compris Enchanted Runes `rx01`…), gemmes, joyaux, objets empilables, objets de lancer, objets sertis, objets de quête ; stats avec leur plage min-max (une plage par stat et par param : deux « +x to <compétence> » ont chacune la leur).
- **Uniques** : numéro sur 15 bits (Median XL, 12 dans D2), nom, mods et niveau requis lus dans `uniqueitems.bin` (✅ Jared's Fragmentor, Horadric Malus). **Sets** : `setitems.bin` et `sets.bin` (nom du set, bonus par nombre de pièces et du set complet).
- Personnage (`.d2s`) : classe, niveau, attributs, objets portés et inventaire (lus, pas encore affichés).
- Robustesse : fichier abîmé, stat inconnue (tables plus anciennes que le jeu) ou lecture décalée = message clair, jamais de blocage.

**Infobulle comme en jeu** (vérifiée sur des captures, puis sur les pages de la documentation officielle)
- Noms et couleurs (nom propre puis nom de base, sans répéter une ligne du nom : reliques, charmes, objets de quête), dégâts, défense, blocage (avec « Base Block Chance », valeur en bleu), exigences en rouge selon le personnage (niveau requis : + « Required Level », niveau des compétences données), classe d'arme et texte de vitesse d'attaque (retrouvé dans `D2Sigma.dll`), bonus de dégâts Force / Dextérité, dégâts élémentaires innés, stats dans l'ordre du jeu, runewords, gemmes et runes, textes d'usage ; « One-Hand Damage » des épées à deux mains pour un Barbare seulement.
- Règles alignées sur la documentation, mesurées à chaque fois sur tout le catalogue : réanimation, classe imposée, textes du jeu (formats 31 / 34, plusieurs lignes, couleurs), charges, poison arrondi, plages autour de 0, valeurs par niveau, Activation Frequency, propriétés à deux stats (min / max pris tels quels)… Pages comparées : Tiered Uniques (909 infobulles), Sacred Uniques (423), Sets (188 infobulles et 51 sets de bonus).
- Ajouts propres à l'éditeur : plages de variance en gris, ventilation par source (B:, RW:, R:, G:, J:), défense de base de l'armure avec sa plage, dégâts de base de l'arme (« Two-Hand Base Damage »…).

**Interface graphique** (`mxl_gui.py`)
- **Point d'entrée : choix d'un personnage sauvegardé** (liste des `.d2s`, relue à chaque ouverture) ; son coffre s'ouvre ; boutons « Coffre du personnage / Coffre partagé » sur la ligne des onglets, coffre partagé affiché pour ce personnage (exigences, bonus) ; personnage et coffre retenus et rouverts au lancement ; coffre absent : grille vide et message.
- **Relecture automatique** : coffre ouvert et personnage de référence surveillés chaque seconde, relus s'ils changent sur le disque (partie jouée) ; coffre attendu ouvert dès qu'il apparaît (plus de bouton « Recharger »).
- Grille 14 × 14 identique au coffre du jeu, 10 onglets, ouverture sur la dernière page vue en jeu ; vraies icônes du jeu (DC6 → PNG) en 3 calques : objet, slots de sertissage vides, objets sertis ; fond de case rouge si le personnage ne peut pas utiliser l'objet.
- **Glisser-déposer** dans une page, vers une autre page (survol d'un onglet) ou **vers l'autre coffre** (survol du bouton de coffre : objet transféré avec ses sertis, arrivée écrite d'abord puis départ, au pire un double, jamais une perte ; relâché hors de la grille : retour au coffre d'origine) ; contrôles et sauvegarde par fichier.
- Panneau de détail : infobulle (+ détails techniques, masqués par défaut), molette active au-dessus des curseurs et des images.
- Barre du bas : nombre d'objets du coffre et de la page, personnage, message courant ; libellés secondaires éclaircis.
- Langue : anglais seul pour le moment (français et allemand retirés le 29/09, récupérables dans l'historique Git) ; toute langue ajoutable par un fichier `lang/<code>.json`.

**Collection** (`mxl_library*.py`, écran « Library », voir `ihm.md`)
- Catalogue : **1 918 entrées** (1 720 uniques, 198 objets de set ; lignes désactivées, 90 reliques vides et 9 objets de quête écartés) ; découvertes enregistrées à l'ouverture des coffres ; avancement sur les objets trouvés.
- Collection des vrais exemplaires : transfert depuis le coffre (aperçu, meilleur exemplaire gardé, options pour les moins bons, destruction réversible jusqu'au transfert suivant), sortie vers le coffre, place normale et éthérée séparées (bascule Normal / Ethereal seulement si les deux existent en jeu), qualité pondérée par les priorités.
- Panneau : même rendu que le coffre pour un exemplaire rangé ; sinon infobulle construite depuis les tables (plages des affixes ; dans le contexte du personnage sélectionné depuis le 02/10 : exigences en rouge, stats par niveau, explications chiffrées), image de l'objet de base (variantes possibles), estompée en vue éthérée.
- **Regroupement par set** (case « Group by set », cochée par défaut) : une ligne par set (pièces trouvées, pièces rangées en information), dépliage retenu ; ligne d'un set : pièces et bonus.
- **Recherche dans le texte complet** (`mxl_library_search.py`) : infobulle, bonus du set, classe des compétences données (« paladin » trouve « +x to Stormlord ») ; tous les mots exigés, « "…" » = expression exacte ; lignes trouvées surlignées ; pièce trouvée par son texte affichée seule, set trouvé par ses bonus affiché replié.

**Qualité et écriture**
- **Qualité de l'objet** : positions des curseurs pondérées par une **priorité** par stat en étoiles (Low 0,5 ; Medium 1 ; High 1,5), pour les uniques, sets et Superior gris sans objet serti ; priorités communes à tous les personnages.
- Écriture sûre : fichier temporaire relu et vérifié, puis remplacement atomique ; refusée si le jeu est ouvert ; en cas d'échec, le fichier d'origine est intact.

**Sens des plages et des curseurs** (30/09, décision retenue) : toute plage s'écrit de la moins bonne à la meilleure valeur (« -4% to Enemy Lightning Resistance [-4 to -5] », « -(5 to 1)% Attack Speed » pour un malus, « Requirements -(21 to 30)% ») ; curseurs d'édition et qualité dans le même sens. Le négatif est un avantage pour : pénétration des résistances ennemies, Requirements, Mana Cost of Skills, Vendor Prices, Stamina Drain (`mxl_rules.LOWER_IS_BETTER`) ; pour toutes les autres stats (Light Radius compris), plus haut = meilleur. Corrige la qualité des objets à « Requirements » ou « Mana Cost » sur une plage (meilleur exemplaire mal choisi jusque-là). Pages de la documentation : sens inverse du site accepté comme différence connue.

**Exécutable Windows**
- `python build_exe.py [--with-editor] [--check]` (PyInstaller, `pip install pyinstaller`) -> `dist/MXL Item Collector/MXL Item Collector.exe` (version publique sans le module `mxl_editor`, dossier à distribuer, environ 30 Mo ; icône : Horadric Cube) ; `--with-editor` : version privée avec le module, dans `dist/editor/`. `data/` non livré : extrait du jeu de l'utilisateur au premier lancement ; traductions livrées + dossier `lang/` à côté de l'exécutable (langue ajoutée ou corrigée sans reconstruire) ; `--check` : lancement avec des dossiers temporaires.

### Mis de côté
- **Collection : objets améliorés par quête ou cube** (27/09 ; Riftwalker's Eye, charmes Heroic doublés par la Mark of Victory…) : même unique (même n°), stats ajoutées à l'objet ; sans stat à variance, tous les exemplaires ont la même qualité -> égalité = exemplaire rangé gardé, un exemplaire amélioré est classé « moins bon » (détruit si l'option est choisie). - **Infobulle d'un objet trouvé et d'un objet non trouvé : différences d'affichage** (29/09, relevées sur Auto Da Fe, laissées telles quelles) :
  1. « One-Hand Base Damage » : ligne ajoutée par l'éditeur (objet trouvé seulement, comme « Base Defense ») ;
