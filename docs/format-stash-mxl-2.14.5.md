# Format des fichiers de coffre — Median XL 2.14.5

Sauvegardes : `%APPDATA%\MedianXL\save`
Installation : dossier d'installation de Median XL (réglage `game_dir`)

## Tables du jeu
- Noms des compétences : `skills.bin` (3018 lignes, 572 octets, index de skilldesc u16 @0x194) → `skilldesc.bin` (793 lignes, 288 octets, nom u16 @0x08) ; sinon clé tbl `skillnameN`. 1064 compétences nommées. Mega Impact (compétence 613) n'a pas de nom : seul le libellé « Mega Impact » est affiché, comme en jeu.
- Stat 83 (+x aux compétences d'une classe) : param = classe (0 Amazon, 1 Sorceress, 2 Necromancer, 3 Paladin, 4 Barbarian, 5 Druid, 6 Assassin) ; la description générique de la table dit « Amazon », corrigée à l'affichage (✅ Imp Talisman : +1 Sorceress).
- Objets supérieurs : `qualityitems.bin` (4 lignes, ligne = sous-qualité 3 bits de l'objet ; 2 mods × (prop, param, min, max) @0x0C). Ligne 0 : armes ED 35–60 ; 1 : armes AR 50–100 + ED 35–50 ; 2 : armures ED 35–60 ; 3 : armures ED 35–50 + Physical Resist 1.
- Objets empilables : drapeau u8 @0x132 de weapons/armor/misc.bin, quantité max u16 @0xE4. Dans l'objet : **quantité sur 9 bits** juste après les données de type (durabilité), avant les sockets (✅ Arrow Quiver 500).
- Dégâts de base des armes : weapons.bin, 1 main min/max u8 @0xFE/0xFF, lancer @0x100/0x101, 2 mains @0x102/0x103. Fixes par type d'arme, non stockés dans l'objet.
- **Objets éthérés** : défense et dégâts de base × 1,25 arrondis vers le bas (`mxl_rules.ethereal_base` ; Totem Shield [42-82] -> [52-102] ; ✅ documentation : Iron Shard) ; la défense enregistrée dans l'objet contient déjà ce bonus (✅ capture de Glyph Basher : 70 affiché tel quel) ; exigences Force / Dextérité −10.
- **Sets** : `sets.bin` (296 octets, ligne = n° du set, `set_id` des objets de `setitems.bin` @0x2C) : nom (n° de texte u16 @0x02, deux lignes de bas en haut : « (Amazon Bow Set) » / « Pantheon »), 8 bonus partiels (propriété, param, min, max en i32) @0x10 par paires pour 2, 3, 4, 5 pièces, 8 bonus du set complet @0x90 (✅ page Sets de la documentation : 47 sets sur 51 identiques).
- **Description des compétences** : `skilldesc.bin` (288 octets, ligne = u16 @0x194 de `skills.bin`) : nom u16 @0x08, description longue u16 @0x0C, **n° d'icône u16 @0x16** = image du fichier d'icônes de la classe (`data\global	hemes\classic_sigma\game\skills\icons-ama/sor/nec/pal/bar/dru/ass.dc6`, `icons-shared.dc6` pour les compétences sans classe ; ✅ captures en jeu : Flamefront 92, Ignis Fatuus 282) ; le champ IconCel de Diablo II (@0x07) est à 0 partout.
- **Compétences** : classe u8 @0x0C de `skills.bin` (0-6, 255 = aucune), niveau requis i16 @0x174 (✅ documentation : Holy Fire 20) ; niveau requis d'un objet = max(base, unique) + stat 92, puis au moins le niveau des compétences données par les stats 97 / 107.
- **Fonctions des propriétés** (`properties.bin`) : 15 = champ min, 16 = champ max (pris tels quels, même si min > max), 17 = param seul, 19 = charges (param compétence, min charges, max niveau), 21 = compétences de classe (classe = valeur fixe de la propriété).
- **Sens d'une stat** (`mxl_rules.LOWER_IS_BETTER`) : valeur affichée meilleure quand elle est plus basse pour la pénétration des résistances ennemies (333-336, format 20 : enregistrée en positif, affichée en négatif), Requirements (91), Mana Cost (228), Vendor Prices (87), Stamina Drain (154) ; plus haut = meilleur pour toutes les autres.
- Nombre de pages du coffre : limite de 10 imposée par le jeu, pas par le fichier. Alternatives : coffre partagé, personnages « mules ».
- Dans `medianxl-YmludGJsdHh0.mpq` (nom en base64 = « bintbltxt »), qui contient 134 fichiers : `data\global\excel\*.bin` + `string.tbl`, `patchstring.tbl`, `expansionstring.tbl`.
- Format MPQ v0, secteurs de 4096 octets, fichiers compressés en PKWARE implode (flag 0x100), non chiffrés. Un lecteur Python maison est dans `mpq.py` (PyPI et GitHub ne sont pas accessibles depuis le bac à sable).
- `itemstatcost.bin` contient 511 stats, avec des enregistrements de 324 octets : id u16 @0x00, save bits u8 @0x19, save add i32 @0x1C, save param bits i32 @0x24.
  - Affichage en jeu : priorité u16 @0x34 (tri décroissant), descfunc u8 @0x36, descval u8 @0x37 (0 sans valeur, 1 valeur avant, 2 valeur après), textes u16 @0x38 (positif) / @0x3A (négatif) / @0x3C (complément).
  - Largeur des stats du personnage dans le `.d2s` (CSvBits) : u8 @0x0A (Force = 11 bits en MXL, or = 25).
  - La couleur d'une ligne vient du code `ÿc` en tête de son texte (ex. `ÿc9Prefixes:` jaune, `ÿc8Mega Impact` or vif) ; bleu par défaut.
  - Regroupement : dgrp u16 @0x3E, dgrpfunc u8 @0x40, dgrpval u8 @0x41, textes u16 @0x42 / @0x44 / @0x46. Ex. stats 0-3 (groupe 1) égales → « +3 to all Attributes ».
  - descfunc (règles vérifiées en jeu) : 1 « +v texte », 2 « +v% texte » (MXL ajoute le +), 20 « -v% texte » (pénétration de résistance), 32 (propre à MXL, régénération de vie) « +v/10 texte », 3 « v texte », 3 « v texte », 4 « +v% texte », 5 « v×100/128 % », 6 à 10 idem + texte complémentaire, 12 « +v ». Les stats cachées ont le texte « FLYING POLAR BUFFALO ERROR ».
- `weapons/armor/misc.bin` (688 / 476 / 1304 lignes) : enregistrements de 424 octets, code @0x80, index du nom u16 @0xF4, type d'objet u16 @0x11E (au moins pour les armes). L'index global (armes, puis armures, puis misc) est utilisé par runes.bin (ex. r02 = 1311). Taille dans le coffre en cases : invwidth u8 @0x10F, invheight u8 @0x110. Nom du fichier d'icône (DC6) : texte @0x20 (ex. `invrin`).
- `gems.bin` (135 gemmes et runes) : enregistrements de 192 octets, nom ASCII @0x00, lettre de rune @0x20, index global de l'objet u32 @0x28, puis **3 groupes (armes, casques/armures, boucliers) de 3 mods (propriété, param, min, max) en i32 @0x30** (48 octets par groupe). Ex. Sol : 60 mana (armes), 40 (armures), 40 (boucliers). ✅ Conforme à l'infobulle en jeu.
- Niveau requis de base d'un objet : u8 @0x13F de `weapons/armor/misc.bin` (ex. Sol = 33, ✅ en jeu).
- Autres champs de `weapons/armor/misc.bin` : Force / Dextérité requises u16 @0x10A / @0x10C, chance de blocage u8 @0x111 (boucliers), bonus de dégâts par Force / Dextérité u16 @0x106 / @0x108 (armes), vitesse (WSM) i32 @0xD8, classe d'arme 4 car. @0xC0.
- `itemtypes.bin` u8 @0x21 : classe imposée (0 Amazon … 6 Assassin, 255 aucune) ; à chercher dans les types parents (ex. `stor` = Sorceress pour le Gambeson).
- `charstats.bin` (196 octets) : bonus de blocage par classe u8 @0x49 (MXL : Amazon 3, Sorceress 3, Necromancer 1, Paladin 1, Barbarian 0, Druid 3, Assassin 3).
- Affixes (magicprefix/suffix, automagic) : niveau requis u8 @0x65. **Niveau requis d'un objet = max(niveau de base, niveau requis de chaque affixe)** ✅ 26 objets sur 26.
- Libellés de l'infobulle des gemmes / runes (clés tbl) : `GemXp3` « Weapons: », `GemXp4` « Armor: », `GemXp2` « Shields: », `ExInsertSocketsX` « Can be Inserted into Socketed Items », `ItemStats1p` « Required Level: ».
- `itemtypes.bin` : 348 types, enregistrements de 228 octets, code sur 4 caractères @0x00, types parents (equiv1, equiv2) i16 @0x04 / @0x06 (ex. bow → miss → weap).
- `properties.bin` : 437 propriétés, enregistrements de 46 octets, 7 fonctions (u8) @0x18, jusqu'à 7 stats (i16) @0x20. Fonctions utiles :
  - 1 = min–max ;
  - 7 = dégâts améliorés (stats 17 + 18) ;
  - 11 = « x % de chance de lancer » (✅ Shark : valeur = **min brut** = chance ; param de la stat = compétence × 64 + niveau ; le min du mod peut être > max) ;
  - 5 = dégâts min plats (stats 21, 23, 159) ; 6 = dégâts max plats (22, 24, 160) ; 15 / 16 / 17 par stat = min / max / param (voir « Infobulle des objets ») ;
  - 17 = valeur « par niveau » portée par param (si param ≠ 0).
- `magicprefix/suffix.bin` et `automagic.bin` : enregistrements de 144 octets, noms tous à « NoDesc » (MXL n'affiche pas les noms d'affixes). 3 mods @0x24 (code de propriété, param, min, max : 4×i32 chacun), actif u8 @0x54, niveau u32 @0x58, groupe @0x5C, niveau max u32 @0x60, niveau requis u8 @0x65, types d'objets autorisés 7×i16 @0x6A, types exclus 5×i16 @0x78.
- **L'id d'affixe enregistré dans l'objet = n° de ligne + 1** : vérifié pour les préfixes et suffixes magiques, les 6 affixes des rares et l'auto-affixe (automagic).
- `rareprefix.bin` (77 lignes) / `raresuffix.bin` (183 lignes) : enregistrements de 72 octets, avec @0x26 une **clé** de string.tbl en ASCII (ex. `PlagueRI` → « Plague »). ✅ Validé en jeu sur 4 rares : 1er nom = ligne `id − 183` de rareprefix, 2e nom = ligne `id` de raresuffix.
- `runes.bin` (237 runewords) : enregistrements de 384 octets, clé du nom @0x40, types autorisés 6×i16 @0x86, types exclus 3×i16 @0x92, runes 6×i32 @0x98 (index global des objets), **7 mods × (propriété, param, min, max) en i32 @0xC0** (fin = −1). Les premières lignes sont des « Jewelword ».
  - Ex. Shark : 167 (param 4), 75 (24–35), 20 (Bloodlust 500, 5 %, niv. 9), 172 (7–9), 15 (20), 124 (−1), 330 (48).
- Index des chaînes : string.tbl à partir de 0, patchstring à partir de 10000, expansionstring à partir de 20000. Les textes sont en UTF-8 et contiennent des codes couleur `ÿc` + 1 caractère.

## Infobulle des objets (✅ vérifiée sur 26 captures en jeu)
- Défense de base (stockée dans l'objet) : tirée dans [min, max] de armor.bin (i32 @0xCC / @0xD0 ; 468 armures sur 476 ont une plage, les 8 autres sont des pièces « Angelic » ou spéciales), **sauf si l'objet a de l'Enhanced Defense (stat 16) : elle vaut alors max + 1**, quelle que soit la qualité (✅ 11 armures du coffre : 5 supérieures ou rares avec ED à max+1, 6 sans ED dans la plage). Les armes n'ont pas de variance de base : leurs dégâts viennent de weapons.bin et ne sont pas stockés.
- Objets de basse qualité : sous-qualité (3 bits) = ligne de `lowqualityitems.bin` (9 lignes, nom ASCII @0x00 = clé tbl) : Crude, Cracked, Damaged, Low Quality, Rusted, Bent, Used, **Discarded**, Broken (✅ « Low Quality Skull Cap », « Discarded Scale Mail »).
- « Two-Hand Damage » n'est affiché que pour une arme à deux mains (weapons.bin u8 @0x11C) : la Throwing Axe a des dégâts 2 mains 1-1 dans la table mais le jeu n'affiche aucune ligne de dégâts (✅).
- **Fonctions par stat des propriétés** (properties.bin, 7 × u8 @0x18, une par stat @0x20) : 15 = min du mod, 16 = max du mod, 17 = param. Les dégâts élémentaires (ex. propriété 104 : stat 50 ← min, 51 ← max) sont donc **fixes** : « Adds 5-6 Lightning Damage » n'a pas de variance (✅ Throwing Axe).
- Stat 415 (descfunc 35, MXL) : « Innate Lightning Damage: 5 (13.0% of Strength) ». **param = élément (octet bas : 0 feu, 1 foudre, 2 froid, 3 poison, 4 magie, 5 tri-élémentaire → chaîne 11600 + élément) + attribut (octet haut = n° de stat : 0 Force, 1 Énergie, 2 Dextérité, 3 Vitalité)** ; valeur = %, dégâts = ⌊% × attribut du personnage / 100⌋. ✅ Throwing Axe param 1 → foudre / Force, 13 % × 43 = 5 ; Hexblade param 512 → feu / Dextérité, 10 % × 43 = 4. Nombre dans la couleur de l'élément, priorité 254 (juste avant « Prefixes »). Vient de l'auto-affixe (propriété 341) ; sa plage min-max n'est **pas** affichée dans l'infobulle (sans signification, choix du 26/09).
- « Throw Damage » n'est affiché que pour les armes de type `thro` (✅ Hexblade : dégâts de lancer 1-1 dans la table, non affichés ; 50 armes dans ce cas).
- Armes de lancer (✅ Javelin) : « Throw Damage: min to max » (weapons.bin u8 @0x100 / @0x101, 102 armes concernées ; dégâts plats de lancer = stats 159 / 160) **avant** « One-Hand Damage », puis « Quantity: n » **après** les lignes de dégâts, avant les exigences.
- Défense affichée = ⌊défense stockée × (100 + stat 16) / 100⌋ + stat 31, avec le pourcentage entre parenthèses (« Defense: 12 (+43%) ») ; la stat 16 n'apparaît pas dans la liste.
- Stats « par niveau » (op u8 @0x54 de itemstatcost ∈ {2, 4, 5}, base u16 @0x56 = 12 = niveau) : valeur affichée = (valeur × niveau du personnage) >> op param (u8 @0x55, = 5). ✅ Shark au niveau 15 : 4 → « +1 to Maximum Damage (Based on Character Level) », 48 → « 22% Bonus to Attack Rating (Based on Character Level) ».
- descfunc 0 : stat non affichée (ex. 372 « Cannot be Unsocketed »).
- Runeword (✅ Shark) : nom du runeword (or), nom de base **sans « Superior »** (gris), lettres des runes sans guillemets (« Eld », or). Dégâts « 7 to 14 (+85%) » : ED de l'objet + du runeword (17/18) entre parenthèses, lignes « Enhanced Min/Max Damage » masquées. Niveau requis = max(objet, affixes, **objets sertis** : Eld = 8).
- Chance de blocage affichée = blocage de base + bonus de la classe du personnage (charstats @0x49).
- Bonus de dégâts Force / Dextérité = ⌊bonus de l'arme × (stat de base + bonus des objets équipés) / 100⌋.
- Dégâts plats égaux 21/23 (22/24) : le jeu affiche la ligne de 23/24 (priorité plus basse) ; 21 + 22 → « Adds x-y Damage ». Poison 57/58/59 : « +⌊v × durée / 256⌋ Poison Damage over durée/25 seconds ».
- Classe d'arme : table de `D2Sigma.dll` @0x101857F8, 24 couples (type d'objet, chaîne) testés dans l'ordre (parents compris) : staf, axe, swor, knif, tpot, jave, spea, bow, pole, xbow, h2h, h2h2, orb (Staff), wand (Staff), blun (Mace), nagi, snag (Polearm), xxx1-3, **scrd / sscd → « Warp Blade »** (✅ capture), ####, wp01. Recopiée dans `mxl_tooltip.WEAPON_CLASS`.
- Noms d'objets : le texte brut porte ses couleurs (`ÿc;` gemmes = violet, comme les runes) et peut tenir sur plusieurs lignes, affichées de bas en haut (✅ « Arcane Shards (2) » en or vif, puis « Cube Reagent »). Nom brut = chaîne u16 @0xF4 de weapons/armor/misc.bin.
- Textes d'usage (D2Sigma 0x1007C930 / 0x10079C10) : types gem / jewl / rune → « Can be Inserted into Socketed Items » ; type char → « Keep in Inventory to Gain Bonus » ; code `box ` → « Right Click to Open » ; code `bkd ` ou **u32 @0x94 de misc.bin = 13** → « Right Click to Read » (✅ Arcane Shards ; MXL peut remplacer ce texte par un texte propre à l'objet, table interne non lue).
- Gemmes / runes : une ligne vide avant chaque groupe « Weapons: / Armor: / Shields: » (chaîne 0xF9E = saut de ligne, ✅ capture Diamond).
- **Texte de vitesse d'attaque** (✅ 6 armes sur 6, 26/09) — trouvé en désassemblant `D2Sigma.dll` (DLL de Median XL, fonction 0x1007CE60) et `D2Common.dll` (ordinal 10592) :
  - v = (images × 256) / ((100 + stat 93 de l'objet − WSM) × vitesse d'animation / 100), divisions entières. Le bonus de vitesse de l'objet n'est **pas** réduit (contrairement au calcul réel des frames). WSM = i32 @0xD8 de weapons.bin (le jeu utilise la stat 68 = −WSM).
  - images et vitesse d'animation : `animdata.d2` (dans `medianxl-YW5pbWRhdGE.mpq`, « animdata » en base64), entrée « classe + A1 + catégorie de l'arme » (ex. `NEA11HS` = 19 images, vitesse 350). Catégorie de l'arme : 4 car. @0xC0 de weapons.bin (1hs, stf, 2ht, bow…).
  - format animdata.d2 : 256 blocs [nombre u32][nombre × 160 octets : nom 8 octets, images u32, vitesse u32, 144 octets de données d'images].
  - catégorie : 1 si v < 10, 5 si v ≥ 28, sinon table de D2Sigma @0x10185690 [v − 10][colonne] ; colonne par classe @0x10185654 (arme, arc / arbalète) : Amazon (0, 2), Sorceress (1, 4), Necromancer (1, 4), Paladin (0, 3), Barbarian (0, 3), Druid (1, 4), Assassin (0, 3). Texte = chaîne 4088 + catégorie (0 Fastest … 6 Slowest). Tables recopiées dans `mxl_tooltip.py`.

- `<Perso>.d2s` : personnage, format D2 1.13c (version 96). Classe u8 @0x28, niveau u8 @0x2B, nom @0x14. Stats après `gf` (id 9 bits + valeur sur CSvBits bits, fin 0x1FF ; l'or 14 = 13 744 ✅ en jeu). Totaux (`mxl_char_stats`, ✅ feuille de personnage de Nekratall) : vie = base × (100 + stat 76) / 100 + Vitalité des objets × vie par Vitalité (charstats.bin u8 @0x46, en quarts) + vie des objets ; mana = base × (100 + stat 77) / 100 + Énergie des objets × mana par Énergie (@0x48) + mana des objets ; défense = défense de chaque objet porté (stockée × (100 + ED) / 100 + plate) + Dextérité / 4.

  - Grilles (`inventory.bin`, 240 octets par ligne, colonnes u8 @0x10, lignes u8 @0x11) : inventaire 15 × 10 (ligne 0, identique pour les 7 classes), cube 15 × 10 (ligne 9), coffre 14 × 14 (ligne 8, ✅ en jeu).
  - Après les objets du personnage : cadavre (`JM` + nombre u16 ; par cadavre 12 octets puis `JM` + nombre + objets), mercenaire (`jf`, puis `JM` + nombre + objets s'il y a un mercenaire ; ✅ Nekratall, 6 objets portés), golem de fer (`kf` + u8, 1 = un objet suit). Mercenaire dans l'en-tête @0xB1 : mort u16, identifiant u32 (0 = aucun), n° de nom u16, type u16, expérience u32. Cadavre non vide et golem : format standard, pas encore rencontrés (une erreur de lecture de ces sections est gardée dans `extra_error` sans rendre le personnage illisible).

Un objet qui change de fichier reçoit emplacement 0 et le panneau du conteneur (4 cube, 5 coffre) ; le champ « équipé » n'est pas touché (le jeu lui-même le laisse : ✅ un objet du coffre de Nekratall garde équipé = 4). À valider en jeu.

## Structure de `.stash`
| Offset | Taille | Contenu |
|---|---|---|
| 0x00 | 4 | version (1) |
| 0x04 | 4 | **dernière page affichée en jeu** (à partir de 0). Vérifié le 25/09 : 4 avec la page 5 ouverte ; 1 dans une sauvegarde à 3 pages (donc pas « nb de pages − 1 ») |
| 0x08 | … | une section par page non vide, à la suite |

Grille d'une page : **14 × 14 cases** (confirmé par capture en jeu), positions x / y de 0 à 13.

**Seules les pages non vides ont une section**, rangées par numéro de page (✅ 26/09 : pages 4 et 5 vidées en jeu = sections disparues). Déplacer un objet vers une page vide crée sa section ; vider une page la supprime.

Section de page : `STASH` + n° de page (u32, à partir de 0) + `JM` + nombre d'objets (u16) + objets.
Les objets se lisent à la suite. Taille d'un objet = 2 + (bits lus arrondis à l'octet). Les objets sertis dans un objet (nombre = champ « nb sertis » de l'en-tête) le suivent directement et ne sont pas comptés dans le nombre d'objets de la page.

## Format d'un objet (format 1.13c standard, bits lus LSB en premier)
Position d'un objet : x et y (4 bits chacun) aux bits 49 et 53 après 'JM' ; les réécrire suffit à déplacer l'objet dans sa page (✅ 26/09, aucune somme de contrôle).

Drapeaux 32 bits (bit 11 serti, bit 21 simple, bit 22 éthéré, bit 24 personnalisé, bit 26 runeword), version 10, emplacement 3, équipé 4, x 4, y 4, panneau 3, code 32 bits, nombre d'objets sertis (1 bit si l'objet est simple, 3 sinon). Pour un objet non simple, on trouve ensuite : id 32, ilvl 7, qualité 4, image (1+3), auto-affixe (1+11), puis les données propres à la qualité :
- basse / supérieure : 3 bits
- magique : préfixe 11 + suffixe 11
